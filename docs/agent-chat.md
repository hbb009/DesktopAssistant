# 对话式 Agent

重启程序，进入 **本地对话 → Agent**。这是原「新版 Agent」的替代入口，主界面已改成聊天，不再需要选择功能、模式、章数等表单。

消息以聊天气泡呈现：用户在右侧，Agent 在左侧。每条消息有「复制整段」按钮，复制全文并保留换行；长消息底部也提供复制按钮。

先选一次工作目录，然后直接描述任务。模型与服务地址沿用「配置」页的本地 Ollama 设置；目录会记住。也可以说“工作目录：D:\小说”。

可以直接这样说：

- “把 https://... 这个网站的正文保存下来。”
- “把目录里的两个文档合并成一个 TXT，保留原文件。”
- “根据目录里的80章小说提炼作者文风，做成可用于其他故事的 Skill。”
- “修改现有大纲，让主角的动机更可信，先安排五章。”
- “加载文风 Skill，按刚才的大纲写第一章。”
- “承接现有小说，从第81章开始续写两章，每章让我确认。”
- “把刚才合并的文件转换成 DOCX。”

未添加附件时，Agent 自动查看工作目录中的材料；通过「添加文件」可以限定输入范围。工作目录里的 SKILL.md 及其参考文件会作为 Skill 识别，不混作小说正文；此前生成的 Skill 也可以直接使用。上一项任务的成果可通过“刚才生成的文件/大纲”等说法继续处理。

“把这个故事大纲写成3000字正文”会优先关联本对话最近有成果的任务，排除辅助剧情记录，不默认重读整个目录。正文目标字数会分配到各段，并根据已完成段落的实际长度调整剩余分配；计数按非空白字符（含标点），目标为约数。被截断的结果不提交，按本步要求有限重试，重试不会无限循环。

旧版本已经建立的大任务仍保留原计划。对于误选大量材料的旧任务，建议重新发送明确的后续要求建立修正任务，而不是继续原来数百步的计划；新任务可查找同一对话此前已完成的成果。

运行中说“暂停”，以后说“继续”。条件不足时，它会在对话中问一个必要问题，你直接补充即可。普通问候和功能询问不会启动文件任务。

小说写好一章，会把章稿发在聊天里。满意请说“确认本章”或明确表示通过；需要修改就直接说意见。单独说“继续”不视作章节通过。修改稿仍需再次确认。移动文件会在聊天里列出源文件和目标，明确回复“确认移动”后才执行。

成果仍保存在工作目录的「Agent成果/任务编号」。右上角「详情」可以打开成果、缓存和日志；「历史任务」可以恢复此前任务，包括旧表单版建立的任务。当前聊天、补充说明和任务进度都会保存。

程序只把当前要求、文件清单和最近任务摘要交给本地模型识别，再校验功能、文件编号与参数后交给原工作流执行。不会把全部聊天和80章正文一次塞进上下文。每步缓存、有限重试、断点恢复与逐章确认机制保留。

自然语言识别依赖本地模型，含糊或超出支持范围的要求可能需要补充；未把80章长篇的最终文风质量视为已验收。


## 2026-11-13：复制、目录与长文字数恢复

- 气泡右上角为复制图标；长消息底部也提供图标，复制成功显示勾号，仍复制完整原文。
- 单一目录按钮：未设置时为“选择目录”，设置后为“工具目录”；点击打开目录，右侧箭头可更换目录。运行中允许打开目录，禁止切换。
- 分段字数按已提交正文动态分配，段落允许合理浮动，整章单独按目标的 ±10% 检查。
- 字数重试修订已保存原稿，最多三次尝试；不硬截断文本，也不自动增大模型窗口。
- 连续字数偏差但正文完整且在上下文安全范围内时，保留草稿交由用户审核，并显示真实字数与未达标提示；不冒充任务已成功完成。
- 每步保留 length-budget.json、length-result.json，修订时增加 repair.json；整章结果保存在 checks/chapter-NNN-length.json。
- 旧任务在重启程序后可从历史任务打开，再发送“继续”；已完成步骤继续复用。


## 2026-11-13：汇总子步骤与修改恢复

- 小说正文先进入逐章确认。剧情事件汇总在确认后完成，下一章仍以已确认剧情为依据。已有任务自动按依赖重新排序，保留步骤编号和有效缓存。
- reduce 汇总使用原计划的 700 字预算，不沿用扩大的 875 字配额。材料已符合预算时原样保留，避免模型无意义扩写。
- 材料过大、输出超长或被截断时，按句子边界拆分材料，分别摘要；多份中间摘要仍过长时，再做下一层汇总。不会截断文本凑字数。
- 子步骤保存在 steps/<步骤>/substeps/<输入指纹>/：input.json、attempts、decision.json、split.json、output.txt、commit.json。修改后的输入使用新缓存，恢复时校验已完成子结果的哈希。
- 子步骤数量、递归深度与上下文均有预算；模型持续无法处理最小片段时保留完整材料并说明需要处理，不能伪造已完成。
- 修订后旧稿确认失效，必须确认新稿；程序退出后可继续任务并复用已完成的子摘要。


## 2026-11-14：文档操作独立分片

- 提取、翻译、校对、改写、摘要使用独立的文档分片路径，不再套用通用写作的“过长就精简”重试。各操作保持自己的语义，只有摘要任务要求摘要。
- 输入预算不足、输出截断或超出单次输出校验长度时，按段落优先、句子次之拆分原文。当前处理区不重叠，前后参考区仅用于理解边界。
- 叶子结果通过后原序合并落盘；合并文件允许超过单次模型输出长度，不再让模型压缩合并结果。
- 完整记录优先放在同一片段；对提取结果，仅移除可明确证明属于前文参考区、且不在当前处理区的重复前缀，保留原始响应及清理日志。不会全局删除相同文本。
- steps/<步骤>/document-substeps/<输入指纹>/ 保存原文区间、请求、原始响应、拆分决策、子结果和哈希提交；最终 document-coverage.json 检查是否完整覆盖源区间。覆盖检查不等同于保证模型所有语义判断正确。
- 子片段至少处理到 80 字下限，设有深度和数量预算；持续无效时保留原文和子结果并说明原因，不发布半成品。
- 已有任务可继续；有效的已完成步骤保留，失败步骤进入新处理路径。
